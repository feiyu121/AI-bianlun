# AI 辩论 · 双人短场直播工作台

从 `fish-workbench` 拆出的独立项目，保留双人剧本辩论，目前采用每题约 6～8 分钟的短场节奏。程序、运行时、素材和数据均位于本目录，可单独启动，不依赖原项目。

## 启动

Windows 安装 Node.js **20.18 或更新版本**，双击 `start.cmd`，也可以在本目录执行：

```powershell
node server.mjs
```

- 工作台：http://127.0.0.1:4320/
- OBS 浏览器源：http://127.0.0.1:4320/scene.html?audio=1
- OBS 画布：**1080 × 1920**，场景按比例适配。
- 当前目录已放入便携 Python；若迁移时未携带 `runtime/python/`，运行 `setup-audio.cmd` 创建 `.venv` 并安装依赖。没有 Node 的 npm 依赖，不需要 `npm install`。

在“模型与语音”填写兼容 Chat Completions 的 API 基础地址、模型 ID 和密钥，保存后测试连接。基础地址示例为 `https://api.openai.com/v1`，不要填写整个 `/chat/completions` 路径。新项目采用独立配置，未迁移原项目的密钥、Cookie、浏览器登录资料或历史记录。

接口报告推理用量时，程序会给后续请求预留相应的输出预算；遇到长度截断，最多提高预算重试一次，并共用原请求的超时限制，不把半句台词当成完整结果。

语音默认使用两种不同的 Edge 神经网络音色，需要联网；也支持豆包云端语音，正反方需分别填写不同的音色 ID。请先分别试听。工作台内的 OBS 预览始终静音；在场景页开启声音，同一时刻只有一个场景页能持有播放权。浏览器若拦截自动播放，点击“开启声音”；OBS 中可通过“交互”点击。

## 工作流程

采用 **剧本库＋现场互动**。主线提前准备，开播后只读库存；弹幕接话、点名、礼物和场间聊天仍可调用模型。库存不足不会现场补写主线。

1. **准备剧本**：在“剧本库”页直接填写自定义辩题，每行一道、每题最多 100 字；也可展开推荐题库多选，或两者混合。重复题目自动合并，每题生成 1～5 份，每批最多 20 份。自定义题目不预设双方立场，由角色自然形成不同意见；题目和人物随剧本保存，参与同样的轮播与观众投票。逐份写作、校验和保存，失败继续下一份，停止保留已完成的稿。导入 JSON 也可入库；导入时检查台词，丢弃外部音频地址和伪造时长。
2. **预合成配音（可选）**：对一份剧本提前合成全部声音。使用相同文本与语音设置播出时复用本地缓存；修改音色、语速或合成设置可能需要重新合成。现场互动的配音仍需实时合成。未预合成的剧本也可播放，播放时按需合成声音。
3. **播放单场**：在直播控制选择库存剧本，或自动优先选择未播、较少播、较久未播的短场；播完收场。短样稿可从剧本库单独播放。
4. **连续直播**：只在通过当前防护检查、已加入轮播的完整短场中选材。下一轮每个话题最多一份候选，多个候选由观众投票；只剩一份时直接预告衔接。默认同一次直播不重复播同一份剧本，库存耗尽收场；勾选“库存播完后允许循环复播”可持续轮转，有其他剧本时避免紧接着重复同一份。
5. **管理与记录**：可将剧本移出/加入轮播而保留原稿，随时导出 JSON。实际说完第一句主线后才记录播出次数；同时保存完整播完次数、上次播出时间和最近播出状态，重启后保留。同题多个版本按整场选播，不拼接不同剧本的段落。

剧本库页的“本份写稿进度”显示大纲、逐段写作、重试、合并消重、播出检查、保存与起播配音预热。分幕进度按实际已处理幕数显示，另列累计句数、字数、估计播出时长、本份耗时和当前模型请求等待时间，不把幕数比例当成剩余时间预测。等待模型超过 30 秒时会追加等待日志；面板显示最近 120 条写稿日志，服务内存保留最近 300 条运行记录。

新稿目标为 **5 段、24 个参考发言轮、约 6～8 分钟**，可自然拆成更多短问短答，每轮最多 260 字。目标是参考，聊透可提前收住，不按时长自动扩写、不为凑轮数重写。生成稿需有完整 5 段；自动轮播接受双方均发言、分段连续且至少 3 段、至少 12 句、估计 3～10 分钟的完整对话。过短样稿和旧长稿仍可手动播放，旧稿原文保留，不截断或自动改写；旧长稿不再参与默认短场轮播。实际时长随语速和观众互动变化。

默认场间先展示本题支持结果 3 秒，随后选题投票 20～30 秒，预告口播后倒计时 2 秒。聊天和投票共用窗口；领先者稳定可提前锁票，零票在最短窗口后自动选库存，平票直接随机裁决，不另加等待。场控可“立即锁票”或“多聊 15 秒”（每次场间最多额外延长 60 秒）。只有一份候选时直接预告衔接。投票输入对应候选的 `1`～`4`，每人一票、允许改票；普通弹幕可继续聊天。场间回复承接上一题实际说过的话，由被点名角色或轮流两位接话，文字和配音完成才发布；进入下一场准备阶段即取消迟到回复，不接入点歌。

弹幕在句间通过反应位接话，支持“你好”“哈哈”等两字短弹幕。文字生成与配音均在后台完成，只有文字和音频都就绪的回复才能入选；准备期间继续主线，未就绪的观众不会挡住其他已准备好的回复。生成上限 25 秒、生成调度等待上限 30 秒，配音另有 30 秒等待上限，普通接话换幕后丢弃旧语境。点名回复就绪后可在最近句间回应，不强制等待 30 秒；两次句间点名至少相隔 10 秒，不紧跟普通接话。指定礼物仍在幕间回应，未准备好则保留到后续幕间，失败可重试；点名失败释放机会，均不播放无声互动或提前计为已回应。播放时将长台词按自然停顿拆成约 40 字以内的片段，原稿不改写，工作台播出进度按片段计数；冷开场与收尾也回应真实弹幕，原 reaction:false 仅禁止填充气氛句。互动文本生成后立即提前配音，优先于尚未开始的主线预读任务，仍保持串行且不打断正在合成的任务；开口时复用已准备的音频。工作台日志记录弹幕接收、入队、生成、配音、待自然停顿插入、失败原因及实际开始回应的延迟；同一观众的普通弹幕和点名均可在一场中多次回应，只保留 15 秒短暂冷却，不设整场次数上限；有效候选中尚未被回应的新观众优先，每人只留一条待回消息，点名改问时会重新生成，旧问题的异步结果不会覆盖新问题。暂停恢复会清空待播互动，停止或换场后的迟到结果不会进入新场。指定计票礼物追加支持票，未映射礼物只记录。默认幕间回应礼物为抖音“墨镜”、快手“甜甜圈”、B站“牛哇牛哇”，可在工作台修改。模型没有配置时仍可播放导入稿，弹幕上墙；社交和实质问题都优先现场生成。生成失败时不拿通用句冒充问题的回答，可选的社交备用缓存每条只用一次，用尽后保持安静。

正赛期间发送整条 `1` / `支持肉包` 加入肉包阵营，发送 `2` / `支持鲸鱼娘` 加入鲸鱼娘阵营；也支持当前辩手名、正方/反方和“加入…阵营”“转投…”等明确指令。只识别整条指令，“肉包你怎么看”等普通弹幕仍用于点名回应。按平台用户 ID 一人一张弹幕票，重复发送不加票，转投会从原阵营移出；缺少 ID 时按昵称去重并在日志标注，无 ID 和昵称则不计入。工作台与 OBS 统一显示支持票及按票数计算的支持条：弹幕入阵营贡献 1 票，礼物票叠加。暂停时可加入，本场结束或停止后封存，本题票数每次开题清零，同时显示本次连续直播的累计支持；累计弹幕支持按平台用户去重，跨题重发不刷累计票，转投只移动该观众的累计弹幕票，历史礼物票保留原归属。新开一次单场或连续直播时重新开始累计；支持票只表示角色支持，不判定观点胜负。场间选题窗口的数字仍投下一场辩题，不加入阵营；不在正赛时不接收阵营加入。礼物固定归属：肉包的爱心 +1、棒棒糖 +3，鲸鱼娘的鲜花 +1、啤酒 +3，乘以实际收到的数量；B站默认对应小心心/辣条/小花花/打call，快手对应小心心/棒棒糖/玫瑰/啤酒。工作台可按平台修改礼物名称或 ID，清空某项可停用。无需先入阵营就能送指定礼物助力，礼物不会自动加入阵营；转阵营只移动弹幕的 1 票，历史礼物票留在送出时对应方。墨镜类礼物继续幕间回应，不加票；未映射礼物只记录。连击按平台归一化后的增量数量计票，消息 ID 去重，缺少稳定消息 ID 不计礼物票。正赛暂停时仍可加票，场间礼物不计本题或下一题票；本题票数每场（含复播）清零，连续直播累计保留。本题支持结果会封存展示，支持票不作为观点正确与否的判定。

“暂停”在句间生效，当前句会说完；“下一幕”中断当前句并跳幕；“停止全部”取消播放、循环、写稿和语音合成。工作台不再提供播出中重写主线的按钮；旧的手动重写 API 仅允许尚未开始的幕。正在运行时不能修改辩手、模型、语音或轮播开关，也不能批量写稿；先备库再开播。

## 人物与表达

剧本可为少量台词附带 `expression`、`delivery`、`listenerReaction`、`pauseBeforeMs`，分别控制说话表情、语气、搭档无声反应和接话前停顿（上限 800ms）。这些信息贯穿写稿、导入导出、预合成和播放，不进入字幕或朗读文本。外部模型提示词见 `生成剧本.txt`；旧稿无需改写，按保守规则补基础表现，不再凭问号或感叹号判断情绪。

两个人按各自模型素材映射表情。说话者与听话者都有轻微视线和头部变化，听话反应短暂出现后恢复，不循环摇头或跳跃；切场、停止、跳幕会清除当前表演。表演跟随实际音频开始，无声预览才使用播放器时间轴。长台词拆为呼吸段时，仅第一段应用接话前停顿和听话反应，避免重复演同一个动作。

豆包语音 2.0 使用独立语气指令，1.0 使用服务支持的情绪；Edge 只做轻微语速变化，不能完整执行自然语言语气指令。具体情感效果仍取决于音色与语音服务。调整表演会改变对应音频缓存；预合成与播放使用相同分段和指令。

- **肉包**反应快，嘴欠、爱抖机灵，嘴硬心软；会认真、认错或护短。
- **鲸鱼娘**看着温和，熟了以后很会阴阳怪气、不紧不慢地补刀；也会冲动、犯懒、心软或被逗笑。

性格不绑定价值立场。每场的两种开场意见可交换分配，讨论中也可以靠近、反转或改口；后续提示词不再反复要求人物“代表”开场意见。

两人是**相爱相杀、嘴上嫌弃心里偏爱**的搭档。可以互相诋毁、挖苦、揭短、拆台，也会吃醋、护短、心软和给台阶。损点来自对方刚才的言行、性格矛盾或明确的虚构假设，不编造真实丑闻。没有每句互怼、甜损比例或固定赢家，保留自然认同和认真说话的空间。

每场开始时抽取虚构的开场状态和共同往事，随剧本保存。状态可随对话发展；虚构世界里已经建立的共同往事可以自然提起，不要求每句话都声明“假设”，也不作为真实新闻或观众经历。

性格只是倾向，不规定每句话如何说。允许短问、认真回答、局部认同、迟疑、暂时岔开和修正。5 段仅保留后台时长与互动节点，不规定定义、成本、案例、小结的固定顺序，不分配固定的先发言者。人物关系和共同规则每次请求只写一份。

默认顺序写稿，并传递累计对话记录，保留早先的承诺、互损和改口。播放时从空白场次记忆开始，只记录实际说完的剧本与互动，不把预读或跳过的台词当成已发生；临场接话、点名、礼物和重写都能读取这一记录。每场最多保留 400 轮，提示词记录预算约 18000 字符；超长时优先保留开场与最近对话，不跨场保存观众资料。记录按原话保留，不额外请求模型总结。

互动不设最低字数：接话最多 80 字、社交最多 60 字、点名最多 160 字、礼物最多 120 字。允许“行吧”“谢啦”，不强制补理由。长稿内容不足时只补有展开空间的发言；消重保留带新结论的回扣，不按较低的文字重合阈值整句删除。

OBS 竖屏按“辩题—双人形象—支持票—主字幕”排列，不重复显示平台自带的弹幕列表；弹幕接收、点名及工作台互动记录照常保留，支持票位于人物下方。主字幕使用 21px 字号（540×960 逻辑画布），根据实际字体、容器宽高测量分页，每页最多三行、字数上限 60，优先在句号或分句标点处换页；较长发言按播放时长估计分页，保留完整原文，分页时间不是逐字对齐。剧本、弹幕接话、点名和礼物回应均在实际开口时进入同一字幕区，互动附带类别及观众名，不再另弹浮卡遮挡正文。礼物助力与幕间回嘴提示放在支持票卡片内、站队提示下方，带“礼物”标识，每六秒轮换，底部至少预留 120px 逻辑画布空间供平台界面使用，完整规则仍显示在工作台。

短场格式和新方案对**重新生成的剧本、尚未开始幕的重写和新生成的临场回应**生效。已有剧本的台词不会自动修改，需要重新生成或使用项目中的 `生成剧本.txt` 在外部模型精剪后导入。

## 直播间与播出防护

支持抖音、B站、快手的观众弹幕与礼物接入。B站/快手需要系统 Edge 或 Chrome，会打开独立采集窗口，登录和验证由使用者手动完成。连接状态与实际平台协议有关，本地启动成功不代表已连接真实直播间。

在“直播间与防护 → 播出防护”可切换“开启本地文本屏蔽检查”，默认开启，点击立即保存，重启后保留。关闭时跳过弹幕、昵称、剧本、字幕与语音文本的本地屏蔽，包括内置词库、谐音和自定义词；格式、长度和音频访问校验继续执行，模型服务自身的规则不受此开关控制。切换后会重新检查库存；开启时命中的稿不参与轮播，关闭后可恢复资格，原文件始终保留。关闭前生成失败、未保存的剧本需要重新生成。`data/` 保存运行数据，包括模型密钥、语音密钥、直播间 Cookie、剧本和音频缓存；`data/script-library.json` 保存轮播开关与播出统计（最近 200 条历史，面板显示最近 8 条）。请勿把该目录公开提交。

## 目录与配置

```text
server.mjs              启动本机 HTTP 服务
lib/http-app.mjs         长场 API、SSE、音频与静态资源
lib/runtime.mjs          单场/连续直播的统一编排
lib/script-library.mjs   剧本选材、轮播开关和持久化播出记录
lib/personas.mjs         性格倾向、人物关系、可交换开场意见与虚构往事
lib/conversation-memory.mjs 写稿与已播对话记录、上下文预算
lib/script/              写稿、播放器、反应位、点名与礼物回应
lib/debate-cycle.mjs     正赛 → 结果卡 → 选题投票 → 预告 → 下一场
lib/topic-vote.mjs       场间选题投票
lib/llm-client.mjs       模型接口、全局并发限制与取消
lib/cloud-voice.mjs      Edge/豆包语音与音频缓存
lib/safety*              播出文本检查
lib/douyin*、live-*      直播平台适配
public/                 工作台、竖屏 OBS 场景、双角色渲染
integrations/            平台采集器及其必要依赖
runtime/python/         当前工作副本的便携 Python
data/                   首次启动创建的本地数据，不纳入版本管理
test/                   长场模块与独立项目回归测试
```

可选环境变量：

| 变量 | 用途 |
| --- | --- |
| `PORT` | 本机端口，默认 4320 |
| `AI_DATA_DIR` | 独立数据目录，默认本项目的 `data/` |
| `AI_LLM_BASE_URL` | 模型 API 基础地址 |
| `AI_LLM_MODEL` | 模型 ID |
| `AI_LLM_API_KEY` | 模型密钥 |
| `AI_PYTHON` | 自定义 Python 可执行文件 |
| `AI_TTS_PROXY` | Edge TTS 代理地址；未设置时读取系统代理 |

模型环境变量用于首次启动默认值，工作台已保存的配置优先。程序不自动读取 `.env`。

## 拆分范围

保留：长场写稿与播放、单场/连续直播、题库与场间选题、弹幕反应、点名、幕间礼物回应、双方语音与 Live2D、直播间接入、剧本库与播出防护。

移除：短场现编辩论、打工/工资/巡查/摸鱼状态机、休息室与聊天模式、点歌、音乐、舞蹈视频与音效、模式切换、旧工作台与相关 API。辩题文本中的“打工、摸鱼”仍属于辩论内容。

拆分时同步修复了手动锁票等待、有限题库耗尽、长句 20 秒时长上限、模型请求并发叠加、双方缺省同音色和停止后迟到任务等问题。原项目目录保持原样。

node tools/test.mjs
# 或 npm test
